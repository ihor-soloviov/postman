# Поштар — планувальник велосипедних маршрутів

Веб-апка для одного поштаря: вносиш адреси — отримуєш порядок обходу від відділення
через усі точки й назад, з картою, чеклістом на телефоні та історією поїздок.

## Що вміє

**Маршрут**
- Рахує порядок обходу як задачу комівояжера з поверненням у депо. Це і дає ті
  «трикутники»: частина адрес свідомо лишається на зворотний шлях, якщо так коротше.
- Реальні велосипедні відстані й час через OpenRouteService (профілі: звичайний,
  електро, шосейний, гірський велосипед, пішки). Без ключа працює по прямій лінії.
- Пошук адрес — через Nominatim (OpenStreetMap): на українських адресах він точний,
  тоді як вбудований в ORS геокодер Pelias часто промахується на сотні кілометрів.
- У поле пошуку можна вставити координати або посилання з Google Maps — тоді геокодер
  не потрібен взагалі. Кожен знайдений варіант показує свої координати, а мітку на
  карті можна перетягнути в правильне місце.
- Мінімізує на вибір час у дорозі або відстань.
- Ручне перетягування точок (↑ ↓), якщо ти знаєш краще за алгоритм — відстань
  перерахується під новий порядок.

**У дорозі**
- Чекліст: «доставлено» / «не застав», коментар до кожної адреси, кнопка навігації.
- Орієнтовний час прибуття на кожну точку з урахуванням хвилин на саме вручення.
- Додавання адреси посеред дня: перерахунок чіпає **тільки те, що попереду**, і
  стартує з останньої відвіданої точки, а не з відділення.
- Працює офлайн: відкриті раніше маршрути доступні без мережі, а позначки й
  коментарі стають у чергу й самі надсилаються, коли зв'язок повертається.
- Ставиться на екран телефона як застосунок (PWA).

**Пам'ять**
- Історія всіх поїздок: скільки точок, кілометрів, план проти факту, нотатка до дня.
- Довідник адрес накопичується сам. У кожної адреси — постійна нотатка (код домофону,
  під'їзд, собака) і вся історія коментарів по ній.

## Швидкий старт (локально)

```bash
npm install
cp .env.example .env     # впиши APP_PASSWORD і SECRET_KEY
npm run dev              # http://localhost:3000
```

Далі в апці: **Налаштування** → місто, адреса відділення і ключ OpenRouteService
(безкоштовний, 2000 запитів на добу: https://openrouteservice.org/dev/#/signup).
Без відділення маршрут не побудується; без ключа ORS маршрут рахується по прямій,
але пошук адрес працює й так — він іде через Nominatim, ключа не потребує.

Після того як відділення знайдено, **перевір мітку на карті** під полем пошуку: її
можна перетягнути або тицьнути в потрібне місце, якщо геокодер став не туди.

## Розгортання на VPS

```bash
# 1. Код і залежності
sudo useradd -r -m -d /opt/postman postman
sudo -u postman git clone <репозиторій> /opt/postman
cd /opt/postman
sudo -u postman npm ci
sudo -u postman cp .env.example .env && sudo -u postman nano .env
sudo -u postman npm run build

# 2. Автозапуск
sudo cp deploy/postman.service /etc/systemd/system/
sudo systemctl enable --now postman
sudo systemctl status postman

# 3. HTTPS (обов'язково — без нього не працюють офлайн-режим і геолокація)
sudo cp deploy/nginx.conf /etc/nginx/sites-available/postman
sudo ln -s /etc/nginx/sites-available/postman /etc/nginx/sites-enabled/
sudo certbot --nginx -d postman.example.com
sudo nginx -t && sudo systemctl reload nginx

# 4. Щоденна копія бази
sudo crontab -e   # 0 3 * * * /opt/postman/deploy/backup.sh
```

Оновлення: `git pull && npm ci && npm run build && sudo systemctl restart postman`.

## Перевірка після оновлення

```bash
npm run build && npm run smoke   # чисті функції + наскрізний сценарій
npm run unit                     # лише чисті функції, миттєво
```

Скрипт піднімає окремий сервер на вільному порту з тимчасовою базою (реальні дані не
чіпає) і проганяє наскрізний сценарій: вхід, побудова маршруту, позначки в дорозі,
перерахунок із замороженими відвіданими точками, ручне перетягування, історія й довідник.

## Змінні оточення

| Змінна | Навіщо |
|---|---|
| `APP_PASSWORD` | пароль для входу (користувач один) |
| `SECRET_KEY` | підпис cookie сесії; `openssl rand -hex 32` |
| `ORS_API_KEY` | ключ OpenRouteService для відстаней і маршрутів; можна лишити порожнім і вписати в апці |
| `DB_PATH` | файл бази SQLite, типово `data/postman.db` |
| `PORT` | порт, типово 3000 |

## Як влаштовано

```
app/            сторінки (маршрут, поїздка, історія, адреси, налаштування) і API
lib/db.ts       SQLite: схема, налаштування, нормалізація адрес
lib/geo.ts      розбір координат, геокодинг (Nominatim, ORS у запасі), матриця відстаней, лінія маршруту
lib/optimize.ts комівояжер: найближчий сусід + 2-opt + Or-opt
lib/trips.ts    планування поїздки: заморозка відвіданих точок, плечі, підсумки
lib/client.ts   fetch + черга змін на час без зв'язку
proxy.ts        пускає далі лише з валідною сесією
deploy/         systemd, nginx, бекап
```

Уся база — один файл SQLite. Копія = скопіювати `data/postman.db` (краще через
`deploy/backup.sh`, він робить це коректно навіть під час запису).

## Обмеження, про які варто знати

- Nominatim просить не більше за один запит на секунду — апка сама тримає цю паузу.
  Тому додавання адрес відчутно неспішне, якщо вносити їх пачкою.
- Безкоштовний тариф ORS: 500 матриць на добу; матриця —
  до 50 точок за раз. Понад 50 адрес в одній поїздці апка рахує по прямій і чесно
  про це попереджає банером.
- Тайли карти тягнуться з OpenStreetMap і офлайн недоступні — сам чекліст без карти
  працює.
- Обмежень на кшталт місткості сумки чи часових вікон поки немає (свідомо).

## Що далі

- База телефонів по адресах — таблиця `phones` уже в схемі, лишився інтерфейс.
- Часові вікна («до 14:00») і поділ на кілька рейсів, коли все не влазить у сумку.
- Імпорт списку адрес одним текстовим блоком.
